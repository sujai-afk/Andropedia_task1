    01 REQUEST TO RECORD

    From typing to a protected record

    As you type, the browser looks at the password’s length, character mix, repetition, sequences, and whether it is commonly used. It turns those checks into a score and tells you what to improve. When you save, the server creates a fresh random salt, hashes salt + password with SHA-256, and stores the hash, salt, score, and other metadata in passwords.db. The plain password is never written to the database.

    02 ANALYSIS ENGINE

    What the heuristic checks

    A strong password is not judged by one rule alone. The analyzer combines several small checks so the result reflects both obvious strength and common ways a password can be guessed.

    LENGTHMeasures characters; 12+ is the passing threshold.
    CHARACTER MIXLooks for uppercase, lowercase, numbers and specials.
    REPEATSDetects 3 or more identical characters in a row.
    SEQUENCESChecks ascending and descending runs of 3+ characters.
    KEYBOARD ROWSFlags runs such as qwerty and asdf.
    COMMON SETCompares against the predefined common-password set.
    DIVERSITYUses unique characters divided by total length.
    SCOPEThis is a project heuristic, not a complete security solution.
    03 SCORE MODEL

    100 points, four components

    The score is a guide for comparison, not a promise of perfect security. Length and character variety build the score, while predictable patterns reduce the benefit of those features.

    LENGTH30
    CHARACTER MIX40
    DIVERSITY10
    PATTERN BONUS20
    TOTAL100 POINTS

    Length awards 5, 15, 25 or 30 points at increasing thresholds. Character types award 10 each. Diversity awards 5 or 10 based on the unique-character ratio. The pattern component starts at 20 and is removed for repeats or sequences. Common passwords are capped at 10; passwords shorter than 4 characters are capped at 15.

    04 SERVER-SIDE TRANSFORM

    Hashing & salting

    The browser can explain the password, but the server is responsible for protecting it. This separation keeps the sensitive storage step away from the visual interface.

    PASSWORD+RANDOM SALT↓SHA-256↓PASSWORD HASH↓SQLITE

    The Node.js implementation uses crypto.randomBytes(16) to create a cryptographically random 16-byte salt, represented as hexadecimal. It hashes salt + password using SHA-256, then stores the hash and salt in separate fields. Plaintext passwords are not stored. Because every save receives a new salt, the same password can produce different hashes. This documents the project’s SHA-256 implementation; SHA-256 is not a password-specific hashing algorithm.

    07 GENERATOR

    Secure password generation

    The generator helps create a password that meets the selected rules without relying on a predictable random function. The finished value is placed into the analyzer so it can be checked immediately.

    CHARACTER OPTIONS↓SECURE RANDOM VALUES↓GUARANTEED TYPES↓FISHER–YATES SHUFFLE

    The generator uses crypto.getRandomValues(), not Math.random(). You choose length and uppercase, lowercase, numbers and special characters. It guarantees at least one character from each selected set, fills the remaining positions from the combined pool, then shuffles the result with Fisher–Yates.

    08 ESTIMATES

    Entropy & crack-time

    These numbers make password strength easier to understand by showing the size of the possible search space. They are estimates, because real attackers prioritize familiar words and patterns first.

    ENTROPYlength × log₂(pool size)Pool: lowercase 26 · uppercase 26 · numbers 10 · special ≈32.
    CRACK-TIMEpool size ^ password lengthAverage tries are half the combinations. Offline: ~10B/sec. Online: ~100/sec.

    These are estimates assuming randomness from the detected pool. Human passwords, dictionary words and patterns can be weaker. The displayed times are not guaranteed real-world attack times.

    WHY FRONTEND + BACKEND?

    The frontend handles interaction, analysis and display. The backend owns the sensitive hashing and database operation. SQLite provides persistent local storage, keeping UI logic and server-side storage responsibilities distinct.
